# Bridge M2 — one Android phone + Windows laptop messaging test

Use one Android phone as **tester_a** and your existing Windows laptop as **tester_b**. This tests two independent accounts and messages against the *same local PostgreSQL database* without needing an Android emulator or second phone. It does **not** test two physical phones, push notifications, real age assurance or public stranger matching.

## Prerequisites
- Latest **Bridge M2** Android APK installed and signed in as \`tester_a\`.
- Original \`Start-BridgeLocalLab.ps1\` PowerShell terminal is still running: http://127.0.0.1:8787/healthz shows \`alive:true\`.
- \`adb reverse tcp:8787 tcp:8787\` is active and phone Chrome also gets \`alive:true\`.
- The originally generated, private **tester_b** passphrase from the setup terminal. It will NOT be regenerated or reprinted by restarting.
- Node.js 22+ installed.
- Local clone of \`rayadinaveen98-ship-it/bridge\`.

## Step-by-step (Windows)
1. **Keep the server PowerShell open.** On the phone, sign in to Bridge as \`tester_a\` and stay on Discover.
2. Open File Explorer at your local **bridge** repository folder. Click the folder's address bar, type \`powershell\`, press Enter. This opens a **second** PowerShell window at the correct folder.
3. Update your local checkout:
   \`\`\`powershell
   git pull
   \`\`\`
4. Start the laptop's second test account:
   \`\`\`powershell
   node .\apps\api\scripts\BridgeSecondTester.mjs
   \`\`\`
5. When prompted, enter the **tester_b** passphrase generated by the server setup. Characters display only as \`*\`, not plaintext, and the helper never writes passphrase or JWT to disk.
6. After \`Laptop tester_b signed in\` and \`Waiting for tester_a\` appear, open Bridge on phone, select **English**, keep **Chat** intent, and tap **Find a conversation**. If either search expires after two minutes, press Find again on phone; laptop retries automatically.
7. On connection, type a message into the phone and send. It should appear as \`PHONE:\` in Windows PowerShell. Type a reply after \`tester_b >\` and press Enter; it should appear in the mobile app.
8. For testing: \`/keep\` requests to retain the connection, \`/refresh\` reloads messages, \`/report\` queues a synthetic report, \`/block\` stops matching and messaging with this synthetic account, \`/end\` closes chat and frees active-match slots; \`/quit\` closes the helper without closing server chat.

## Troubleshooting
- \`Cannot reach Bridge test backend\`: keep the *first* PowerShell backend window running and confirm \`http://127.0.0.1:8787/healthz\` works in laptop Chrome.
- \`invalid_credentials\`: you likely entered \`tester_a\`'s passphrase instead of \`tester_b\`'s. The terminal helper always uses tester_b and deliberately does not accept arbitrary identities. Do **not** post screenshots showing passphrases.
- \`too_many_login_attempts\`: retry after 15 minutes (lab process restart clears in-memory counters but should not be used to bypass login restrictions).
- \`active_match\`: prior conversation may still be open. Use **End random chat** in the phone's conversation menu. If stuck, inspect DB state; do not delete records blindly.
- \`No match yet\`: verify both sides selected English and started searching close together; search expires after roughly 2 minutes.
- Phone no longer connects over USB: run \`.\adb reverse tcp:8787 tcp:8787\` again from the Android \`platform-tools\` folder.
- Passphrase lost: no automatic reset is implemented. Do not share DB password or private keys; a controlled synthetic-lab credential reset workflow is needed.

## Important boundaries
All traffic is restricted to 127.0.0.1 local test host (Android accesses it via USB port reverse). This is **not** a secure production deployment. Never use your regular account passwords or invite real users. The account eligibility flags are synthetic fixtures only.
